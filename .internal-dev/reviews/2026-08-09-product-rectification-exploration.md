### 2. Terminology and concept model

- `plan_definitions` (kind `SESSION_PLAN` | `TASK_TEMPLATE`) is the "unified plan/task definitions" table; saved tasks and session plans are the same record distinguished by kind. `work_task_definitions` (migration 015, `promoted_plan_id` → `plan_definitions.id`) is a second task-definition carrier. Three task-creation pathways: PlanService saved-plan-chat → TASK_TEMPLATE; TaskService chat drafts (`/api/tasks/drafts/{conversationId}/approve`); WorkTaskService (project work tasks, operations CREATE/EDIT/BIND/PROMOTE/SUBMIT/RETRY).
- "plan" has 4 meanings (session plan, saved task template, workflow node content, job item PLAN); "task" has 3 (TASK_TEMPLATE kind, work task, umbrella run concept in `task_run_locations`/`run_summaries` with `source_kind` task|workflow|job); "job" has 3 (`job_definitions`, legacy `orchestration_jobs`/`orchestration_job_items`, background `agent_jobs` chat jobs).
- Parallel discriminators with inconsistent spellings: `work_assignments.assignment_type` (TASK_RUN/WORKFLOW_RUN/JOB_RUN/AGENT_MESSAGE/WAIT_FOR_MESSAGE/REPORT) vs `task_run_locations.source_kind` vs `task_run_native_links.native_kind` vs `workflow_runs.run_type`/`run_output_artifacts.run_type` vs `skill_exact_assignments.target_type` (AGENT/PROJECT/JOB/TASK/WORKFLOW/CHAT_SESSION).
- Duplication: 4 definition/run pairs with parallel JSON snapshot shapes (plan/workflow/job/work_assignment); `run_output_artifacts` (legacy/inert) vs `output_publications` (canonical); two chat persistence stacks (`ai_chat_memory`/`ai_chat_session_metadata` vs `plan_chat_messages`); workspace identity triple (`workspace_type`+`workspace_key`+`workspace_identity`) repeated on 8+ tables; old + new schedule/reaction table pairs (`agent_schedules`/`agent_event_reactions` dropped in-file, replaced by `schedule_definitions`/`reaction_definitions`).
- Schema constraints for tasks exist only in `plan_definitions`: `inputs_json`/`outputs_json`/`validation_criteria_json` (+ `PlanFieldDefinition` name/type/required/array/description/"optional schema") — populated for TASK_TEMPLATE only; SESSION_PLAN explicitly has no structured inputs/outputs; `work_task_definitions` has no schema/criteria columns. `plan_definitions.deliverables_json` is a legacy not-null column ignored by repositories.
- `prompt_profile` (legacy column) vs `WorkTypeProfileService` ("maps structured work type profile values and legacy prompt profile values") vs `plan_definitions.planning_task` — three overlapping profile concepts.

### 4. Scheduling

## Risk Assessment

1. **Branch strategy is the single biggest risk/decision**: planning against the wrong base (rebuild on `core` vs resume/rebase `sprint/20260729-163244-project-dashboard` vs master) invalidates most phase detail. The target model implies a full product rebuild; `core` provides the new framework foundation; the sprint branch provides the last complete implementation to salvage (services, fragments, tests, schema). Deleted code is recoverable via `git show 8b6cdcc1~1:`.
2. **Spec/schema/doc corpus describes a deleted system**: any plan must decide whether specs become "product contract to re-achieve" or are rewritten wholesale; the orphaned 83-table `schema.sql` needs a revival/slimming decision.
3. **Target model reverses settled decisions** (no-project-root, closed three-kind workspaces, cron scheduling, plan≡task unification, skill trust gates): spec supersession must be explicit (new ARCH entries + decisions) or planners will fight the existing contract.
4. **Concurrency/idempotency machinery must be preserved**: schedule firing operation keys, assignment fences, context bindings, task-run idempotent ops are mature; the rectification should extend, not regress, them.
5. **Security/confinement posture**: no authN/authZ exists (single-operator alpha); "root agent vs subagent" capability tiering is a new capability model, not wiring. Process confinement unproven → executable/shell/package features fail closed.
6. **Docs sweep is large** (12+ technical, 14 end-user, api indexes) and is a classic under-scoped tail.
