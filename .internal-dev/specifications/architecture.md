# Architecture Specification

## Intended Contract

Magenta is a Spring Boot and Spring AI operational assistant. Runtime behavior should stay small, observable, cancellable, and grounded in concrete user workflows. Controllers stay thin, services own use-case behavior, repositories own persistence details, and user-facing executable work should prefer `task` terminology while preserving compatibility with existing `plan` names until a deliberate rename is planned.

## Canonical Task-Run Identity Matrix

| family | immutable definition | native run / canonical `taskRunId` | other identities and cardinality | retry/resume and filesystem conclusion |
| --- | --- | --- | --- | --- |
| task | `plan_definitions.id` | `plan_runs.id`; one row represents one saved-plan execution and its id is immutable | `work_assignments.id` is separate queue/lease identity; one assignment may link the run but never names its path | Saving status updates preserves the run id. A new operator execution allocates a new native run; Phase 02 records resume attempts and retry/replay lineage. Native UUID text passes the canonical component validator, so reuse is valid. |
| workflow | `workflow_definitions.id` | `workflow_runs.id`; one row represents one workflow execution and its id is immutable | `workflow_node_runs.id` is deterministic child identity (`<workflowRunId>-<index>`), not task-run identity. Job and assignment links are contextual and separate. | Waiting/resume updates the same workflow run. A new execution allocates a new run. Node retries remain children/attempt facts and cannot rename the run path. Native UUID text is reusable. |
| job | `job_definitions.id` | `job_runs.id`; one row represents one job execution and its id is immutable | `job_assignment_id` remains assignment identity. Work-item run ids are embedded child-run references in `work_item_runs_json`; each child plan/workflow retains its own native run id and location. | Job status/work-item progress updates preserve the job run. A new assignment-owned execution allocates a new job run. Native UUID text is reusable; work-item and assignment ids are never aliases. |

The companion `task_run_native_links` row stores one native family/run pair and optional explicit assignment, workflow-child, or job-work-item linkage. It does not replace native status ownership. No linkage is inferred from names, timestamps, paths, or status.
