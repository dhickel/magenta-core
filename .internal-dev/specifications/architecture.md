# Architecture Specification

## Intended Contract

Magenta is a Spring Boot and Spring AI operational assistant. Runtime behavior should stay small, observable, cancellable, and grounded in concrete user workflows. Controllers stay thin, services own use-case behavior, repositories own persistence details, and user-facing executable work should prefer `task` terminology while preserving compatibility with existing `plan` names until a deliberate rename is planned.

## Cross-Domain Operational Read Model

`RunSummaryService` and `RunMeasurementRepository` provide rebuildable, non-authoritative runtime read models over native task/workflow/job status. `OrchestrationController` scopes agent run-fragment requests before calling those services, and `RunOperationsFragments` renders bounded source-kind groups plus on-demand attempts, elapsed time, lineage, and artifact facts. `WorkspaceExplorerService` remains filesystem-only; the agent Files surface composes `#agent-run-groups` beside the explorer without adding persistence edges to explorer services or path-derived identity.

Ordered migration ownership covers contiguous resources 001-011, including artifact access/search/retention, immutable skill snapshots/trust, runtime summaries/measurements, schedule/reaction hardening, warm-bookkeeping compatibility, and agent materialization/context persistence with strict serialized keys and operation idempotency. SQLite FTS5 is probed at runtime: supported deployments use scope-constrained FTS5, while unsupported deployments show search as unavailable with no fallback. Artifact retention defaults to `PRESERVE` (keep indefinitely) until an explicit authorized policy/action applies, and pins, active access, claims, references, lineage, or reconciliation state can block removal. Projects still have no filesystem root authority. Host process confinement remains unproven, so workspace-bound shell, skill executable authorization, and package ingestion fail closed; instruction approval does not imply executable safety.

## Artifact, Skill, Runtime, and Automation Architecture

- **Task-run and artifact state:** one native run id is the canonical task-run id inside an `AGENT` or `USER` workspace. Lifecycle reservations, attempts, assignment leases, and writer claims live in SQLite; run/output locations remain trusted root-relative filesystem values. Publication crosses the database/filesystem boundary through operation identity, staging, digest verification, create-only promotion, and reconciliation. Access/search/preview/retention are authorization-first layers over publication records, not explorer features.
- **Skill state:** candidate discovery is read-only and provenance/digest qualified. Root precedence and exact assignment specificity select one candidate but grant no trust. Explicit approval snapshots confined source bytes immutably; model disclosure and activation consume only snapshot records. Revocation and activation audit remain durable. Project discovery, package ingestion, and executable resources are capability-gated and unavailable under current root/confinement facts.
- **Observability state:** native plan/workflow/job rows remain status truth. Typed invocation measurements preserve repeated model/tool calls and nullable facts. `run_summaries` is a replaceable cache derived from native status, attempts, and exact linked domain identifiers. Health denominators exclude active/unavailable records; audit composition does not infer links by time, name, or path.
- **Schedule/reaction state:** definitions are revisioned and soft-deleted; historical snapshots and audit retain their original revision. Scheduler ownership uses persisted owner/fence claims suitable for the current topology. Firings and dispatches carry canonical operation keys/request digests, append-only attempts, exact lifecycle links, and recovery state. Reactions additionally persist root/parent causation, dedupe, and loop/depth/rate suppression. Shared evaluators accept immutable input and a supplied clock; simulation has no mutation-capable collaborators.
- **Retention:** no policy means `PRESERVE`/keep indefinitely. Lifecycle actions are explicit and scoped, and protection from active work/access, references, lineage/legal pins, and unresolved reconciliation overrides deletion policy.
